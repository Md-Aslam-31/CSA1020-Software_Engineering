    GIT & GITHUB · YOUR PRACTICE GUIDE

    One contribution.
    Six clear steps.

    Follow the workflow, then mark each lesson complete.

    Use a repository you are allowed to change. In the example commands, replace YOUR-USERNAME and YOUR-FORK with your own GitHub username and fork name.

    1. 01

      Fork and clone

      12 min

      Open a public sample on GitHub and select Fork. Choose your account, create the fork, and clone its URL to your computer.

      git clone https://github.com/YOUR-USERNAME/YOUR-FORK.git
cd YOUR-FORK
      Practice lesson 1 ↗
    2. 02

      Create a feature branch

      18 min

      Create a branch for one focused improvement. This keeps the main branch stable while you work.

      git switch -c feature/my-improvement
      Practice lesson 2 ↗
    3. 03

      Build, test, and commit

      15 min

      Make a small change, run the project's checks, and inspect the diff. Stage only the files you intend to include.

      git diff
git add path/to/changed-file
git commit -m "Describe the improvement"

      For this LearnLoop project, run node --test to check the progress calculator.

      Practice lesson 3 ↗
    4. 04

      Push and open a pull request

      20 min

      Push your branch. On GitHub, select Compare & pull request, verify the target repository and base branch, and describe what changed and how you tested it.

      git push -u origin feature/my-improvement

      For a practice merge you control, target your fork's main branch. An upstream pull request needs the upstream maintainer's acceptance.

      Practice lesson 4 ↗
    5. 05

      Review and respond

      10 min

      Review the files, tests, and behavior. Leave specific feedback, fix it in a follow-up commit, and push to the same branch. The existing pull request updates automatically.

      git add path/to/fixed-file
git commit -m "Address review feedback"
git push

      Ask another account for a formal review. GitHub authors cannot approve their own pull requests; label a one-account exercise as a self-review.

      Practice lesson 5 ↗
    6. 06

      Merge and reflect

      15 min

      When feedback is resolved and required checks pass, a maintainer can merge the pull request. Confirm GitHub shows Merged, then sync your local main branch.

      git switch main
git pull --ff-only origin main

      Use your repository's actual default branch name if it differs from main. Mark a lesson complete after you practice it; navigation alone never completes it.

      Practice lesson 6 ↗
